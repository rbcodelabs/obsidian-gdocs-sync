# Google Docs Sync v0.10.2

## Bug fixes

- Fixed full-vault sync stopping with “Immutable object integrity failure: metadata mismatch” when Google Drive identifies a binary upload as an image or another recognized content type. Binary blobs tolerate that metadata change while their downloaded bytes still undergo length and SHA-256 checks. Folder and JSON history-record MIME checks remain strict. ([#39](https://github.com/rbcodelabs/obsidian-gdocs-sync/pull/39))
- Metadata verification errors now name the mismatched field, making failures easier to diagnose without resetting sync state. Redact filenames and identifiers before sharing diagnostics publicly. ([#39](https://github.com/rbcodelabs/obsidian-gdocs-sync/pull/39))

## Verification

- 395 unit/integration tests across 24 files passed, including regression-first coverage for strict JSON record MIME validation.
- TypeScript and the production build passed; 34 offline acceptance-harness checks passed.
- Review preserved the blob byte/hash checks and restricted the MIME exception to binary blob declarations.
- Fresh live Google account/desktop sync, large-vault resync, resumable uploads and a 24-hour soak were not verified for this release. Offline checks are not live acceptance evidence.

## Update and limits

Update Google Docs Sync through BRAT or your host's plugin updater, then reload the plugin. This release contains `main.js`, `manifest.json`, and `styles.css`. No new settings, OAuth scopes, or reauthentication are required.

Full-vault sync remains an explicit opt-in beta with its existing limits. Keep independent backups and test on a disposable vault first. Preserve local journals and managed remote history if a failure persists; do not clear integrity evidence or delete remote objects as a workaround. This patch does not establish that any particular vault has completed synchronization.

The unrelated HTML-sync feature PR #17 is not included.
