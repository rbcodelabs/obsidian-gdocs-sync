## Full vault sync is now reachable — behind an explicit opt-in

v0.8.0 shipped the managed Google Drive vault transport, but gated it behind a **compile-time** flag that is `false` in every release build. The published v0.8.0 `main.js` contained zero references to `registerSyncProvider`, so no user could reach the feature regardless of settings.

This release moves that gate from compile time to runtime. ([#32](https://github.com/rbcodelabs/obsidian-gdocs-sync/pull/32))

- The transport now ships in the plugin bundle and is registered with Geode **only after you turn it on**, via a new **Full vault sync (beta)** toggle under *Full vault sync (Geode)* in plugin settings. Default is off.
- Enabling requires explicit consent. The toggle does not flip on click — it opens a dialog stating the limits that apply today and what has not been verified, and only registers the transport if you confirm.
- On a host that cannot support it (no secure secret storage, or ordinary Obsidian rather than Geode) the toggle renders disabled with the specific reason, instead of failing when clicked.
- Turning it **off** persists immediately but requires a plugin reload or app restart to unregister the transport from the running session. The host's sync registration API ties teardown to plugin unload, so there is no in-process unregister; the plugin says so rather than pretending otherwise.

**Existing behavior is unchanged unless you opt in.** Updating to v0.9.0 does not begin syncing anything, and does not register a sync provider.

## Google Docs sync actions in the file menu

- "Sync to Google Docs", "Pull from Google Docs" and "Open in Google Docs" now appear directly in the native file menu — the view-header overflow menu, file-explorer right-click, and tab-header right-click — for markdown notes, not only in the command palette. ([#33](https://github.com/rbcodelabs/obsidian-gdocs-sync/pull/33))
- The push/pull logic shared with the existing `sync-current-note` / `pull-current-note` commands was extracted so both entry points behave identically.

## Limits that apply if you enable full vault sync

- **100 MiB per file.** Larger files are not synced.
- **Immutable history with no garbage collection.** Every revision is retained; Drive storage use grows with every change and is never reclaimed automatically.
- Google Docs and Google Tasks managed paths are excluded from the vault transport, as are community plugins and community plugin data.

## Verification

Observed on the merged release commit:

- **370 passing tests across 23 files**, clean TypeScript (`tsc --noEmit`), successful production build. CI unit tests green.
- The opt-in flow was exercised end-to-end against a real Geode 0.19.x build, driving the actual UI: with the toggle off the host lists no sync provider; clicking the toggle opens the consent dialog and still registers nothing; confirming registers `google-drive.full-vault` and it appears in the host's Sync provider list; the setting persists to `data.json`.
- A consent-dialog layout bug found during that verification — the dialog's buttons rendering outside the visible modal at every window size tested — was fixed before release.

## Not verified

This release changes **how the transport is gated. It does not make the transport itself more proven.** Everything listed as unverified in v0.8.0 remains unverified:

- Live Google sign-in for the vault transport, beyond the earlier two-client manual acceptance run.
- Independently authorized clients, conflict handling and fresh-device vault reconstruction at scale.
- Interrupted or resumed uploads, large-vault performance, long-running multi-day convergence.
- The 24-hour soak, and the `tests/live/` acceptance driver, which needs real Google credentials and was not part of this release's automated gate.

The beta label and the consent dialog are what stand between a user and that unverified code. Treat full vault sync as an early, explicitly gated capability, try it on a test vault first, and keep independent backups of any vault you bind.

## Update

- Update Google Docs Sync through BRAT and reload Obsidian or Geode. This release includes `main.js`, `manifest.json`, and `styles.css` — `styles.css` is required for the consent dialog to lay out correctly.
- No new Google scopes are requested. An existing connection continues to work; no disconnect/reconnect is required.
- Requires Obsidian 1.4.0 or later. Full vault sync additionally requires Geode with secure secret storage.
