## A documented connection API for other plugins

Other Obsidian plugins can now trigger and observe this plugin's Google connection flow through a stable, documented surface instead of reaching into internals. ([#35](https://github.com/rbcodelabs/obsidian-gdocs-sync/pull/35))

```js
const gdocs = app.plugins.plugins['obsidian-gdocs-sync'];
if (gdocs?.connectionApi) {
  const { email } = await gdocs.connectionApi.requestConnection();
}
```

Before this release the only way to do that was `app.plugins.plugins['obsidian-gdocs-sync'].auth.connect()` — undocumented, fire-and-forget (no way to know when or whether it finished), with no guard against two callers starting competing sign-in flows. That path was never a supported contract and could have changed without notice.

`connectionApi` provides:

- **`requestConnection({ force })`** — awaitable. Resolves with the connected account once the OAuth callback completes. If already connected it resolves immediately **without opening a browser window**, unless you pass `force: true`. Concurrent callers are deduped onto the same in-flight promise rather than racing separate flows. Rejects on OAuth state mismatch, a callback missing tokens, or no callback within 5 minutes.
- **`isConnected()`** / **`getConnectedEmail()`** — current connection state.
- **`disconnect()`** — clears stored tokens and the connected account.
- **`onConnectionChange(cb)`** — subscribe to connect/disconnect, returns an unsubscribe function.

Connection changes are also broadcast on `app.workspace` as `'gdocs-sync:connected'` and `'gdocs-sync:disconnected'`, each firing with a `{ email: string | null }` payload — use whichever fits your plugin's existing event wiring.

Everything reachable through `connectionApi` is part of the contract and will not change in a breaking way without a major version bump. Anything else on the plugin object — including `auth` — remains an implementation detail. `src/auth/GoogleConnectionApi.ts` carries the full annotated contract.

### A hazard the new semantics introduced, handled in the same change

"Already connected → resolve without opening a browser" is the right default for an API other plugins call, but it is wrong for one existing caller. The **Reconnect Google Account** button appears precisely when a token is present but Google has revoked it: `isConnected()` is `true` while the connection is in fact dead. Left alone, that button would have silently done nothing. It now passes `force: true` explicitly. This was not a defect users could hit in v0.9.0 — it is a new sharp edge, found and closed before release.

## Nothing changes if you don't use it

This is an additive API surface. Sync behavior, settings, the connect/disconnect buttons and the OAuth flow itself are unchanged for anyone not calling `connectionApi`. No new Google scopes are requested.

Observed on the release commit ([`36ba9c8`](https://github.com/rbcodelabs/obsidian-gdocs-sync/commit/36ba9c8b63d40cb177529b5512f5b129a19d656c)), in a clean worktree after `npm ci`:

- **379 passing tests across 23 files** (`npx vitest run`), clean TypeScript (`npx tsc --noEmit`, exit 0), successful production build (`npm run build`, exit 0). CI unit tests green on the PR.
- `tests/auth/GoogleAuth.test.ts` holds 17 tests, all passing; **10 are specific to this API**: connection status, concurrent-caller dedup (asserting both callers receive the *same* promise object and the browser opens exactly once), the already-connected no-op, the `force: true` path, the success flow and its `gdocs-sync:connected` broadcast, listener subscribe/unsubscribe, disconnect and its broadcast, the 5-minute timeout, and OAuth state-mismatch rejection. The remaining 7 are the pre-existing Geode host-callback and disconnect/callback-race tests, retained through the rebase.
- **The API is confirmed present in the shipped `main.js`**, not compiled out — `connectionApi`, `requestConnection`, `getConnectedEmail`, `onConnectionChange` and both workspace event names all appear in the built bundle. This check exists because v0.8.0 shipped a feature that was absent from the published bundle; it is now verified rather than assumed.

The branch was rebased across the v0.9.0 work (the `TokenStore` secure-storage refactor and Geode host-callback support) and the two feature sets were merged by hand in `GoogleAuth.ts` and its test suite, rather than either side being taken wholesale.

### A deliberate behavior change worth knowing

An OAuth callback whose `state` does not match now **rejects the in-flight connection attempt outright**. Previously a mismatched callback was ignored and the flow stayed open, so a later correct callback could still complete it. Failing fast is the documented contract for `requestConnection()`; a test that encoded the old retry-after-mismatch assumption was rewritten to match. In practice a state mismatch means the callback did not originate from the flow this plugin started, which is exactly the case the CSRF check exists to reject.

## Not verified

- **A live Google sign-in through the new code path was not exercised in this release's gate.** Coverage is the unit suite driving `requestConnection` and `handleCallback` directly with a stubbed browser-open and stubbed `requestUrl`. The OAuth flow is unchanged in shape from v0.9.0, but "unchanged in shape" is an argument, not an observation.
- No second plugin has consumed `connectionApi` end to end against a real Obsidian install — the contract is proven by its tests and its types, not by a real consumer.
- The 5-minute timeout is verified with fake timers, not against a real stalled sign-in.
- No UI changed in this release, so there is no visual verification to report.
